1. Gemini hides allowed values on 179 of 182 tools, and rejects 1
Why it matters
The model never sees the allowed values (enum), defaults or examples, so it can send arguments the API then rejects. GOOGLEDRIVE_UPDATE_PERMISSION doesn't convert at all.
Fix
The drop is by design, so treat it as a decision: for example, list the allowed values in the parameter description. Separately, fix the nested permission object that from_callable can't parse.
Evidence
Cause. Gemini declarations are built from a Python function signature (FunctionDeclaration.from_callable), so only types survive. Dropping enum is intentional and pinned upstream in test_gemini_provider.py, AFC_CASES.

2. OpenAI strict mode can't be used for 114 tools
Why it matters
With OpenAIResponsesProvider(strict=True) these tools are quietly sent without strict mode, so their arguments get no structured-output guarantee.
Fix
Declare the properties of free-form objects (97 tools, for example array items typed as bare object). Keep arbitrary-key maps (27 tools) only where the keys are truly dynamic.
Evidence
Cause, in the SDK's own words (to_strict_json_schema). The provider then falls back to non-strict and only logs a warning: _openai_responses.py, lines 84 to 99.

3. 227 of 930 tools carry no action hint, so approval rules can't see their intent
Why it matters
A tool tagged with none of readOnly, create, update or destructive can't be targeted by require_approval or tag filters. 12 of them have destructive-sounding names (delete, remove, revoke).
Fix
Add the hint that matches each tool's effect. Start with the destructive-sounding ones.
Evidence
Why the tags matter, in the code. Composio's Tool Router filters and gates tools by these tags (ToolRouterTag). Its require_approval docstring reads: "Tools with any of these tags need the user's approval before they run."

5. Vertex conversion passes for all 930 tools in this run
Why it matters
The fix from Composio PR #4751 is reflected in the current adapter results.
Fix
Keep the adapter package current and rerun this check when Composio schemas change.
Evidence
Fixed upstream in #4751, merged 2026-11-13, replacing the top-level-only stripping with a recursive allowlist. It ships in Python SDK 0.33.0 (release PR #5394, open when checked). The results below reflect the analyzed Composio commit and adapter versions listed above.
Cause, in the code. The adapter removes examples only from top-level properties (composio_google/provider.py, lines 43 to 60). Nested examples and file_uploadable reach Vertex's schema parser, which rejects unknown fields.

How the checks run


  • Real adapters, not copies. Each check imports the installed provider package (for example composio_google.GoogleProvider) and calls its own wrap_tool.
    • 

  • Offline. Network sockets are blocked during conversion, and any attempt to execute a tool raises.
    • 

  • One bad tool never stops a run. A missing provider SDK is reported as unavailable, not as a failure.
